## 2024-05-24 - [CRITICAL] XSS in Plugin editing via dangerouslySetInnerHTML\n**Vulnerability:** XSS vulnerability through direct injection of raw plugin edit data into the DOM via dangerouslySetInnerHTML without sanitization.\n**Learning:** The initial instinct to use DOMPurify for this issue was incorrect because it is code editor content where tags like < and > are common and valid parts of the language syntax (like XML, HTML, or type parameters). DOMPurify treats this as invalid HTML and strips it, leading to silent data corruption for the user. Additionally, this app uses Next.js SSR which means DOMPurify crashes when run on the server side unless instantiated carefully.\n**Prevention:** Use a simple HTML escape function that turns special characters into safe HTML entities when passing raw user code input to dangerouslySetInnerHTML. Avoid standard DOM sanitizers for raw code/text editors.
